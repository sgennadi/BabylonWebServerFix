# BabylonWebServerFix v1.0.4

**Stable Windows x64 release** of BabylonWebServerFix, a self-contained C# / .NET 10 command-line utility for Babylon Pro 12 compatibility with Microsoft IIS and Apache HTTP Server/XAMPP.

## What changed since v1.0.0

- **IIS native filtering is now the default.** Ordinary `install` uses built-in IIS Request Filtering and does not require or download Microsoft URL Rewrite.
- **Safe IIS mode migration.** Switching to `--iis-mode rewrite` installs/verifies the Rewrite rule before removing the managed native rule; switching back installs/verifies the native rule before removing only BabylonWebServerFix's Rewrite rule.
- **Existing RewriteModule is preserved and reused.** Detection uses Microsoft.Web.Administration plus a read-only `appcmd` cross-check. If registration is confirmed, no MSI is downloaded or reinstalled.
- **Fail-closed Rewrite installer handling.** Official Microsoft HTTPS URLs, local/UNC MSI input, adjacent offline MSI priority, native WinTrust signature validation, and Microsoft publisher validation are enforced.
- **New `remove-iis` action.** Removes only BabylonWebServerFix-managed IIS compatibility rules without changing Apache or WinINet cleanup state.
- **More regression coverage.** Windows CI now passes **65 offline smoke tests** covering CLI behavior, native filtering, installer-source policy, signer validation, migration options, and RewriteModule/appcmd parsing.

## Verified on BASE-IMAGE

- Babylon Pro 12 translated with IIS native filtering active.
- Native → URL Rewrite migration completed successfully and Babylon translation was confirmed.
- URL Rewrite → native migration completed successfully while IIS remained Started.
- v1.0.4 `install --iis-mode rewrite --dry-run` recognized the already registered RewriteModule and skipped MSI download.
- `remove-iis` backed up IIS, removed the native Babylon rule, and a subsequent `status` confirmed both managed IIS rules absent while IIS remained Started.
- Apache/XAMPP compatibility and Babylon translation were also verified on a test workstation.

## Known limitations

- The native IIS rule returns HTTP **404.19** for the Babylon query substring and applies site-wide to matching query strings; a brief initial Babylon error-page flash was observed on one workstation.
- A normal `http://localhost/` response with the final v1.0.4 native configuration has not yet been explicitly verified.
- The appcmd disagreement/fallback path and non-dry-run no-redownload path have not been separately reproduced on a workstation.
- Multi-user/GPO/SYSTEM deployment and some error/rollback paths still need wider validation.
- The executable is **unsigned**; SmartScreen or application-control policy may prompt or block it.

## Quick start

Run from an elevated Command Prompt:

```cmd
BabylonWebServerFix.exe status
BabylonWebServerFix.exe install --dry-run
BabylonWebServerFix.exe install
```

To use Microsoft URL Rewrite explicitly:

```cmd
BabylonWebServerFix.exe install --iis-mode rewrite
```

To remove only this project's IIS rules:

```cmd
BabylonWebServerFix.exe remove-iis
```

Review the [validation matrix](https://github.com/sgennadi/BabylonWebServerFix/blob/main/docs/TEST_MATRIX.md) and test the target workstation before broad deployment.
