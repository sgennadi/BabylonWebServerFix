# BabylonWebServerFix v0.1.3 Preview

A Windows x64, self-contained .NET 10 command-line utility that helps Babylon Pro 12 coexist with local Microsoft IIS and Apache HTTP Server / XAMPP installations.

## Included in this preview

- **IIS:** narrowly targeted URL Rewrite `AbortRequest` rule for Babylon 12 localhost requests. Can download/install Microsoft IIS URL Rewrite 2.1, validating Authenticode trust and the Microsoft publisher using native WinTrust (no PowerShell invoked).
- **Apache 2.4 / XAMPP:** managed configuration rule, backups, syntax validation, rollback and direct XAMPP console restart in the original user/session. An unchanged rule does not restart Apache again.
- **Babylon:** automatically restart in the original interactive user session when it was running, with a safe non-elevated restart plan.
- **WinINet:** clear legacy temporary web cache for non-special Windows user profiles; optional per-user next-logon cleanup. Cookies and saved credentials are not intentionally removed.
- **Deployment:** `install`, `status`, `remove`, `cache-only`, `restart-apache`, `--dry-run`. Logging and next-logon cleanup are **off by default**.

## Download and run

Download **BabylonWebServerFix.exe** from this release's **Assets** section.

Run from an **elevated Command Prompt** on a test Windows x64 workstation:

```cmd
BabylonWebServerFix.exe status
BabylonWebServerFix.exe install --dry-run
BabylonWebServerFix.exe install
```

No PowerShell execution-policy changes or separate .NET runtime installation are required.

## Validation

- GitHub Actions Windows build and smoke tests pass for v0.1.3 prior to this release.
- On one Windows workstation, Babylon Pro 12 translated English to Hebrew while XAMPP Apache was listening on TCP/80.
- This preview has **not** been fully validated on a clean IIS install, particularly the new native WinTrust verification of Microsoft's URL Rewrite MSI, or for broader Apache/Babylon environments.
- IIS `AbortRequest` and Apache HTTP `403` are **not equivalent**. Verify the web server and Babylon work side by side before enterprise deployment.
- The EXE is **unsigned**. SmartScreen or local application-control policies may require publisher trust/signing for widespread deployment.

**Status: Pre-release.** Test on one workstation before deploying to labs or production.
